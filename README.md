## The Problem

27 million Nigerians live with hypertension. 4.2 million with diabetes. Nearly 60% miss medications regularly — not because they don't care, but because no safety net exists between clinic visits. CarePulse closes that gap.

---

## What It Does

1. **Clinical staff register patients** via a web dashboard — capturing diagnosis, medication schedule, dose times, language preference, and consent.
2. **Google Gemini generates personalized reminders** in the patient's language (English or Pidgin English).
3. **Africa's Talking delivers SMS** to any Nigerian phone — no smartphone or internet required.
4. **Patients reply CONFIRM or SNOOZE** — replies are tracked via webhook.
5. **Adherence scores are calculated automatically** — medication (70% weight) + appointments (30% weight) over a rolling 30-day window.
6. **Low-adherence patients receive weekly lifestyle tips** — auto-generated by Gemini, targeted to their specific condition.
7. **Clinicians see real-time adherence data** on the dashboard.

## Local Setup

### 1. Clone the repository

```bash
git clone https://github.com/Nadira3/carepulse.git
cd carepulse
```

### 2. Start OpenMRS and PostgreSQL

```bash
cd openmrs   # or wherever your docker-compose.yml lives
docker compose up -d
```

Wait for OpenMRS to finish initializing (~3 minutes). Check:

```bash
curl http://localhost:8080/openmrs/ws/rest/v1/system/setting
```

### 3. Install backend dependencies

```bash
cd backend
npm install
```

### 4. Configure environment variables

```bash
cp .env.example .env
nano .env
```

Fill in all values — see [Environment Variables](#environment-variables) below.

### 5. Run database migrations

```bash
npx prisma migrate deploy
npx prisma generate
```

### 6. Seed an admin user

```bash
npx ts-node src/scripts/seed-admin.ts
```

Or create one manually via the API:

```bash
curl -X POST http://localhost:3000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "admin@hospital.com",
    "password": "SecurePass123!",
    "firstName": "System",
    "lastName": "Admin"
  }'
```

### 7. Start the API server

```bash
npm run dev
```

### 8. Start the reminder worker (separate terminal)

```bash
npm run worker
```

### 9. Serve the frontend

```bash
cd ../frontend
python3 -m http.server 8000
```

Open `http://localhost:8000`

## Reminder System

### How scheduling works

When a prescription is created with dose times (e.g. `["08:00", "20:00"]` for twice daily):

1. A `ReminderSchedule` row is created for each dose time.
2. The worker cron runs every 15 minutes and checks which schedules fall in the next window.
3. Gemini generates a personalized message in the patient's language.
4. Africa's Talking sends the SMS.
5. Patient replies `CONFIRM` or `SNOOZE`.
6. Africa's Talking POSTs the reply to `/api/reminders/webhook`.
7. Adherence score is recalculated.

### Cron schedule

| Job | Schedule | Description |
|-----|----------|-------------|
| scheduleDueReminders + sendPending | Every 15 min | Core reminder delivery |
| markTimedOut | Every hour | Mark no-reply as missed after 4 hours |
| sendLifestyleTips | Monday 09:00 WAT | Weekly tips for <50% adherence |

### Africa's Talking webhook setup

In your AT dashboard, set the incoming SMS callback URL to:

```
https://yourdomain.com/api/reminders/webhook
```

This must be HTTPS in production. Use nginx + Let's Encrypt (see [Production Deployment](#production-deployment)).

## Adherence Scoring

Scores are calculated on a rolling 30-day window with weighted components:

```
adherenceScore = (medicationScore × 0.7) + (appointmentScore × 0.3)

medicationScore  = confirmed doses / scheduled doses × 100
appointmentScore = attended appointments / scheduled appointments × 100
```

| Score | Status | Action |
|-------|--------|--------|
| ≥ 80% | On Track (green) | Routine reminders only |
| 50–79% | At Risk (amber) | Routine reminders only |
| < 50% | Non-Adherent (red) | Routine reminders + weekly lifestyle tips |

## Production Deployment

### AWS EC2 (current setup)

The system runs on Ubuntu 24 on AWS EC2 with:
- OpenMRS + PostgreSQL in Docker
- Node.js backend as two processes (API + worker)

### Setting up HTTPS with nginx

```bash
sudo apt install nginx certbot python3-certbot-nginx

# Configure nginx
sudo nano /etc/nginx/sites-available/carepulse
```

```nginx
server {
    server_name yourdomain.com;

    location /api {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location / {
        root /var/www/carepulse/frontend;
        try_files $uri $uri/ /index.html;
    }
}
```

```bash
sudo certbot --nginx -d yourdomain.com
```

### Running with PM2

```bash
npm install -g pm2

# Start API
pm2 start "npm run start" --name carepulse-api

# Start worker
pm2 start "npm run worker:prod" --name carepulse-worker

# Save and enable on reboot
pm2 save
pm2 startup
```

### Registering an SMS Sender ID (MTN delivery)

Africa's Talking requires a registered sender ID for delivery to MTN Nigeria numbers. Submit a sender ID registration request through your AT dashboard. Allow 5–7 business days for NCC approval.

## Known Limitations (Current Phase)

- **MTN Nigeria delivery** — requires registered sender ID. Glo, Airtel, and 9mobile deliver without one.
- **Voice calls** — architecture supports it (Termii voice) but not yet implemented.
- **WhatsApp** — planned for Phase 5 via Meta Business API.
- **Appointment reminders** — schema and adherence tracking built, scheduler not yet wired.
- **Reports page** — placeholder only.
- **Patient profile page** — not yet built.
