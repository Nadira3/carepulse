## Daily Operations

### Starting the system after a server reboot

If the server restarts, run these commands in order:

```bash
ssh ubuntu@3.93.195.129

# 1. Start Docker containers (OpenMRS + PostgreSQL)
cd ~/openmrs
docker compose up -d

# Wait 3 minutes for OpenMRS to initialize, then:

# 2. Start the API server (Terminal 1)
cd ~/emr-service
npm run dev

# 3. Start the reminder worker (Terminal 2 — new SSH session)
cd ~/emr-service
npm run worker
```

Verify everything is running:

```bash
curl http://localhost:3000/health
# Should return: {"status":"ok","service":"emr-service",...}
```

### Checking if the system is running

```bash
# Check API
curl http://3.93.195.129:3000/health

# Check Docker containers
docker ps

# Check recent logs
cd ~/emr-service
# API logs are in the terminal where npm run dev is running
# Worker logs are in the terminal where npm run worker is running
```

## Patient Registration Workflow

### Step 1 — Register the patient

1. Log into the dashboard
2. Click **Add New Patient** or navigate to **Add Patient** in the sidebar
3. Fill in Step 1 (Personal Details):
   - First name, last name
   - Age
   - Gender
   - Phone number (Nigerian format: +2348XXXXXXXXX)
   - Preferred language (English or Pidgin English)
4. Click **Next**
5. Fill in Step 2 (Clinical Details):
   - Primary diagnosis (Hypertension / Diabetes Type 2 / Both)
   - Secondary conditions (optional)
   - Treating clinician name
   - Ward / Clinic
6. Click **Next**
7. Fill in Step 3 (Enrolment):
   - Enrolment date (defaults to today)
   - Check the consent checkbox — **patient must be informed of the SMS programme first**
8. Click **Register Patient**

The system will:
- Create the patient in OpenMRS (generates a unique OpenMRS ID)
- Save the patient to our database
- Redirect to the Medication Setup page

### Step 2 — Set up medications

After patient registration, you are automatically taken to the Medication Setup page.

1. For each medication:
   - Enter drug name (e.g. Amlodipine)
   - Enter dosage (e.g. 5mg)
   - Select frequency (Once daily, Twice daily, Three times daily, Four times daily)
   - Set the time(s) for each dose — this is when the SMS reminder will fire
2. Click **Generate Preview** to see a sample Gemini-generated reminder message
3. Optionally set appointment date and department
4. Click **Approve & Save**

The system will:
- Create a clinical encounter in OpenMRS
- Create prescriptions linked to that encounter
- Create reminder schedules for each dose time
- The worker will automatically send SMS at those times every day

## Reminder System

### How reminders fire

The worker checks every 15 minutes for dose times due in the next window. If a patient has a dose at 08:00, the 07:45 or 08:00 cron run will schedule and send the SMS.

Reminders are sent automatically — no manual action needed.

### What patients receive

Patients receive an SMS like:

> *"Baba, e don tey wey you dey manage your BP well. Wey una Amlodipine 5mg dey? Remember to take am today o. Reply CONFIRM when done or SNOOZE for 1 hour."*

Messages are generated by Google Gemini in the patient's preferred language.

### Patient replies

| Reply | Action |
|-------|--------|
| `CONFIRM` | Dose marked as taken, adherence score updated |
| `SNOOZE` | Reminder resent after 1 hour |
| No reply after 4 hours | Dose marked as missed, adherence score drops |

### Viewing reminder history

Go to **Reminders** in the sidebar. Filter by type (Medication/Appointment/Lifestyle) or status (Pending/Sent/Failed/Cancelled).

## Adherence Scoring

### How scores are calculated

Scores are calculated automatically every time a patient confirms or misses a dose. They cover the last 30 days.

```
Score = (medication adherence × 70%) + (appointment adherence × 30%)
```

### Score categories

| Score | Colour | Meaning | Action |
|-------|--------|---------|--------|
| ≥ 80% | 🟢 Green | On Track | Routine reminders only |
| 50–79% | 🟡 Amber | At Risk | Monitor closely |
| < 50% | 🔴 Red | Non-Adherent | Weekly lifestyle tips auto-sent |

### Where to see scores

- **Dashboard** — adherence bar shows distribution across all patients
- **Patients list** — each row shows On Track / At Risk / Non-Adherent badge
- **Patient profile** — (coming soon) detailed score breakdown

---

## Lifestyle Tips

Patients with adherence below 50% automatically receive a weekly lifestyle tip every Monday at 09:00 WAT. These are generated by Gemini and tailored to their specific condition (Hypertension or Diabetes).

Example tip:

> *"Good morning Ada. Small steps dey matter. Try cut down salt for your food this week — e go help your blood pressure. You dey do well!"*

No action is required from clinical staff.

## Troubleshooting

### Patient registration fails

**Error: "Registration failed: OpenMRS bad request"**

This usually means:
1. OpenMRS is not running — check `docker ps`
2. The patient identifier already exists — use a different identifier
3. Network issue between the API and OpenMRS

Run:
```bash
docker ps | grep openmrs
curl http://localhost:8080/openmrs/ws/rest/v1/system/setting -u admin:Admin123
```

---

### SMS not delivered

**Possible causes:**

1. **MTN numbers** — MTN Nigeria blocks SMS from unregistered sender IDs. This is a carrier restriction. Glo, Airtel, and 9mobile work without registration. MTN delivery requires registering a sender ID with NCC through Africa's Talking (5–7 business days).

2. **Insufficient AT balance** — Check your Africa's Talking account balance at account.africastalking.com. Each SMS costs approximately ₦2.20–₦5.40 depending on carrier.

3. **Phone number format** — Numbers must be in international format: `+2348XXXXXXXXX`. Numbers stored without the country code will fail.

4. **Worker not running** — Check that the worker process is active.

```bash
import dotenv from 'dotenv';
dotenv.config();
import { prisma } from './src/config/prisma';
import bcrypt from 'bcrypt';
async function main() {
  const hash = await bcrypt.hash('NewPassword123!', 10);
  await prisma.user.update({
    where: { email: 'admin@hospital.com' },
    data:  { passwordHash: hash }
  });
  console.log('Password reset done');
  process.exit(0);
}
main();
"
```

## Database — useful queries

Run these on the server when you need to check data directly:

```bash
docker exec openmrs-postgres-1 psql -U emr_user -d emr_service -c "YOUR QUERY HERE"
```

```sql
-- Count all patients
SELECT COUNT(*) FROM patients;

-- See all patients with phone numbers
SELECT "givenName", "familyName", phone, "primaryDiagnosis" FROM patients;

-- See all active prescriptions with dose times
SELECT p."givenName", p."familyName", rx."drugName", rx.dose, rx.frequency, rx."doseTimes"
FROM prescriptions rx
JOIN patients p ON rx."patientId" = p.id
WHERE rx.active = true;

-- See today's reminders
SELECT p."givenName", r.type, r.status, r."sentAt", r."confirmedAt"
FROM reminders r
JOIN patients p ON r."patientId" = p.id
WHERE r."scheduledAt"::date = CURRENT_DATE
ORDER BY r."scheduledAt";

-- See reminder schedules (what will fire tomorrow)
SELECT p."givenName", rs."doseTime", rs."frequencyHours", rs."isActive"
FROM reminder_schedules rs
JOIN patients p ON rs."patientId" = p.id
WHERE rs."isActive" = true
ORDER BY rs."doseTime";

-- See adherence scores
SELECT p."givenName", p."familyName", ar."adherenceScore",
       ar."medicationConfirmed", ar."medicationScheduled"
FROM adherence_records ar
JOIN patients p ON ar."patientId" = p.id
ORDER BY ar."adherenceScore" ASC;

-- See failed SMS messages
SELECT p."givenName", p.phone, r.message, r."failedAt"
FROM reminders r
JOIN patients p ON r."patientId" = p.id
WHERE r.status = 'FAILED'
ORDER BY r."failedAt" DESC
LIMIT 20;
```

## Backup

### Database backup

```bash
# On the server
docker exec openmrs-postgres-1 pg_dump -U emr_user emr_service > backup_$(date +%Y%m%d).sql

# Copy to your local machine
scp ubuntu@3.93.195.129:~/backup_$(date +%Y%m%d).sql ~/Desktop/
```

Run this weekly or before any major update.

### Restore from backup

```bash
docker exec -i openmrs-postgres-1 psql -U emr_user emr_service < backup_20260611.sql
```

## Security checklist

Before going live at ISTH:

- [ ] Change default admin password
